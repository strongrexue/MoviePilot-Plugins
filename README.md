# 胖虎 MoviePilot V3 插件集

> 三个独立的 MoviePilot V3 插件：**建订阅 → 找资源 → 美化库**
> 仓库地址：<https://github.com/strongrexue/MoviePilot-Plugins> ｜ 更新记录：[Releases](https://github.com/strongrexue/MoviePilot-Plugins/releases)

本仓库只维护 V3 插件（索引文件 `package.v3.json`，对应 MoviePilot V3 的插件市场）。
三个插件互相独立，**装哪个都行、互不依赖**，也可以三个一起装。

## 插件一览

| 插件 | 插件 ID | 版本 | 一句话定位 | 分类标签 |
| --- | --- | --- | --- | --- |
| 胖虎订阅中心 | `SubscribeCenter` | 1.18.1 | 全自动开播 / 定档发现并写订阅，含番剧与国漫 | 订阅 · 工具 |
| 胖虎媒体中心 | `TgMediaCenter` | 1.13.39 | 把 TG 频道资源自动送进 115，只推你真正缺的集 | 工具 · 媒体 |
| 胖虎封面中心 | `EmbyCoverCenter` | 1.6.32 | Emby 媒体库封面生成 + 备份 + Emby 任务中心 | Emby · 媒体库 · 封面 |

三者串起来是一条链：

```text
胖虎订阅中心  →  胖虎媒体中心  →  胖虎封面中心
自动发现并订阅     从 TG 捞资源      给媒体库做好看封面
番剧/国漫/电影     只推缺的          13 套布局 + 备份恢复
```

**插件 ID 一经发布永不改名**（目录名 = ID 小写，配置前缀 = `ID_` 小写）。改名或升级版本都不会动你已有的配置与数据。

## 安装

1. MoviePilot → 设置 → 插件 → **添加自定义插件仓库**，填入本仓库地址
   `https://github.com/strongrexue/MoviePilot-Plugins`；
2. 到插件市场找到要装的插件，点安装 —— 三个插件的索引条目都声明了 `release: true`，
   安装时会直接拉本仓库 GitHub Release 里的压缩包；
3. 手动安装（不想加仓库时）：从 Releases 下载对应 zip，解压到 MP 的 `app/plugins/` 下，
   目录名必须是插件 ID 的小写形式（`tgmediacenter` / `subscribecenter` / `embycovercenter`）。

> 装完记得去插件页把开关打开。三个插件的 V3 界面都是 **Vue 联邦组件**，
> 更新后如果界面没变化，先按一次 `Ctrl+Shift+R` 硬刷新。

## 胖虎订阅中心 · SubscribeCenter

**只做三件事：发现 → 去重 → 写订阅。** 版本控制、洗版、下载优先级全部交给 MP，插件不插手。

### 数据源

| 源 | 覆盖 | 特点 |
| --- | --- | --- |
| TMDB | 全球电影 / 剧集 | 按开播日与定档窗口发现，主力源 |
| AniList | 番剧 + 国漫 | `countryOfOrigin=CN` 的 `title.native` 就是中文名，国漫默认包含 |
| 豆瓣 RSS | 榜单 / 想看 | 经 RSSHub，每条榜单可独立配置（开关 / 条数 / 窗口 / 想看） |

Bangumi 已降级为**标题翻译层**：只用它的 `name_cn` 换中文名再去搜 TMDB——
因为用日文原名搜 TMDB 命中率是 0。Simkl / JustWatch 未实现。

豆瓣路线的实际表现（实测）：电影上映榜单有精确日期 + 豆瓣 id，最准；剧集类没有日期，
靠「TMDB 还有没有未播集」判定；电影榜单类没有日期则跳过。

### 身份分级 L1–L4

写入前对每条候选做身份判定，**宁可漏，绝不写错**：

| 级别 | 条件 | 动作 |
| --- | --- | --- |
| L1 | 来源自带确定性 ID（TMDB id / AniList id） | 直接写 |
| L2 | 映射缓存命中 | 直接写 |
| L3 | 标题 + 年份精确搜索，且年份硬校验通过 | 写入 |
| L4 | 仅标题相似 | **只列「待确认」，永不自动写入** |

写入前还会**实时复查**宿主的活跃订阅**和订阅历史**——宿主自己的 `async_add()` 只按身份幂等，
不查历史，订阅完成后记录会移入 `SubscribeHistory`，不查历史就会重复写。
首次运行强制 dry-run；每日写入上限默认 30（建议不超过 50）。

### 播出日自动启停

宿主在 `subscribe_mode=spider` 下每天随机跑 32 轮 `subscribe_refresh`，每轮把状态 R/P 的订阅
逐条搜站点。插件每天 00:05 按「今天该不该搜」给每条订阅改一次状态：

| 情形 | 状态 |
| --- | --- |
| 还有缺集，且在保留窗口内 | `R`（订阅中） |
| `auto_toggle_lookahead_days` 内有新集要播 | `R` |
| 全部已播且已入库 | `S`（暂停） |
| 首集还没播 | `S` |
| 缺集超出保留天数，且窗口内没有新集 | `S` |

三条安全约束：

1. **暂停只能写 `S`**，不能写 `P` —— `P`（待定）仍然会被宿主搜索；
2. **绝不用 `Subscribe.note` 存标记**，接管记录存在插件数据里；
3. **只动自己暂停过的订阅** —— 你手动改回 `R` 就视为你接管，插件立刻放弃该条。

### 电影单独判定

锚点取 TMDB 的 **数字发行日（type=4）**，洗版取实体发行（type=5）；
**不是**顶层 `release_date`——那是首映 / 院线日，会比数字发行早几周到几个月。
电影不看「已入库」，因为洗版订阅入库后宿主会故意保持 `R` 等 priority=100。

**缺集口径**（1.17.6 起）：只认宿主的 `Subscribe.lack_episode`（宿主逐集核库的结果，唯一口径、
零成本）。`Subscribe.note`、`DownloadHistory`、`MediaServerItem.seasoninfo` 都不算入库。
代价是宿主自身算错时会跟着早停一集。

### 发现页（MP 左侧「发现」）

整页 Vue 界面，版块包括：顶部统计卡、数据源一览、上次运行明细、**订阅卡片配色**
（写宿主自定义 CSS，可给订阅中 / 待定 / 暂停三种卡片上色）、视图 tab（日历 / 发现流水）、
月历网格、今天首播海报墙、集数缺口、状态 tab、卡片网格。

> 「预览」和「立即运行一次」是**启动 + 轮询**两段式（前端 4 秒轮一次）：
> 一次发现要一两分钟，网关几十秒就断，同步请求必然 502。

### 排障

- **写了 0 条** → 先看流水里的判定原因；L4 待确认不会写入，首次运行强制 dry-run；
- **重复订阅** → 检查「订阅历史」是否被清过；插件查的是宿主历史表；
- **订阅被莫名暂停** → 插件只暂停自己接管过的条目（插件数据里有记录），你手动改回 `R` 即释放；
- **AniList 报错** → 官方停服时插件会明确写「临时停服，不是本插件的问题」，可临时关源。

## 胖虎媒体中心 · TgMediaCenter

监视 Telegram 资源频道，命中后先按你的订阅和媒体库判断「缺不缺集」，**只推真正缺的**；
顺带提供历史消息缓存、订阅回搜、私聊链接转存和 TG 通用转发，结果全部通知到 MP 的通知渠道。

### 能干什么

| 模块 | 做什么 |
| --- | --- |
| ① TG 凭证 | Telethon 运行时、登录向导、会话持久化、对话列表缓存、全局冷却与 FloodWait 退避 |
| ② 115 网盘 | 扫码 / Cookie 登录态、空间配额、分享转存、磁力 / eD2k 离线、分批提交 |
| ③ 资源监控 | 监听频道消息 → 识别片名 / 年份 / 季集 → 订阅门禁 + 媒体库缺失判断 → 只推缺的 |
| ④ 历史消息缓存 | 流水线实时写入 + 位点增量 / 时间范围同步，支持检索与统计 |
| ⑤ 订阅回搜 | 宿主新增订阅后自动回搜缓存历史，补推缺失资源（事件触发 + 定时兜底） |
| ⑥ 通用转发 | 两级匹配（关键词 / 扩展名）→ 转发原消息到目标会话，可置顶与内容转换 |
| ⑦ 消息交互 | 私聊机器人发 115 分享 / 磁力 / eD2k 链接 → 直接转存并回执（带已转存查重） |
| ⑧ 运行详情 | `/overview` 聚合状态与流水（可翻页、筛选决策、关键词搜索） |
| ⑨ 发现页入口 | 在 MP 左侧「发现」分区注册整页入口，内容即运行详情 |
| 通知 | 四类：转存完成 / 转存失败 / 缓存回搜 / 链接转存回执 |

**推送目标**（监控规则与缓存回搜都可选）：

| 选项 | 说明 |
| --- | --- |
| 智能（默认） | 115 已启用且已登录 → 转存；否则仅记录 |
| 115 网盘 | 分享转存 / 磁力 eD2k 离线 |
| TG 转发 | 把原消息转发到目标会话 |
| 仅记录 | 不推送，只落流水（便于先观察） |

**缺失判断**（「仅缺失」开启时生效）：先过订阅门禁（未订阅直接跳过），再查宿主媒体库——
按「片名+年份 → 仅片名 → 名称变体（`片名 (年份)` 等）」三层做**定向查询**，命中后复核库内年份，
同名不同年的翻拍剧不会被误判「已有」。三层全是定向查询，代价与媒体库规模无关。

### 工作流程

```text
Telegram 频道消息
   ↓  事件监听（聚合窗口：默认 3 秒内的消息合并处理）
消息流水线
   ↓  识别（片名 / 年份 / 季集 / 115 分享 · 磁力 · eD2k 链接）
订阅门禁 + 媒体库缺失判断
   ↓  只保留「已订阅且缺集」的资源
推送队列（同一目标合并下发，单批默认 ≤ 20 条链接）
   ↓
目标：115 转存 / TG 转发 / 仅记录
   ↓
通知（成功 / 失败，含来源频道与链接）+ 运行详情流水留档
```

三条旁路：**历史缓存**（流水线顺带落盘，供检索与回搜）、**订阅回搜**（新增订阅秒级触发回搜，
定时兜底覆盖插件离线期）、**私聊转存**（直接对机器人发链接，不经过监控规则）。

### 首次配置（5 步）

1. **TG 凭证**（必填）：API ID / API Hash / 手机号 → 发码登录 → 刷新对话列表
   （后续所有会话下拉都取自这份缓存）；
2. **115 网盘**：扫码或 Cookie 登录 → 选转存目录 → 单批上限（默认 20）；
3. **资源监控**：开启 → 建规则（来源频道、推送目标、关键词、扩展名、置顶、内容转换）
   → 建议开启「仅缺失」只推缺集；
4. **消息缓存**：勾选要缓存的频道 → 选同步方式（相对天数 / 绝对时间范围）→ 打开订阅回搜；
5. **通用转发**：建规则（逻辑一按关键词、逻辑二按扩展名，命中即转发到目标会话）。

改动随底部「保存配置」生效。

### 排障

- **会话下拉里没有频道** → 先点「刷新对话列表」，下拉只认这份缓存，不会实时拉 TG；
- **发码提示 502** → 是反代读超时，后端其实已经发码了，直接去 TG 收；
- **发码说太频繁** → Telegram 侧约 60 秒一次的最小间隔，等一会再来；
- **凭证总是存不住** → 必须先「保存配置」再发码；会话串存插件数据不存配置项，
  保存配置是整份覆盖，放进配置会被清掉。

## 胖虎封面中心 · EmbyCoverCenter

面向 Emby / Jellyfin，给媒体库生成好看的封面，也管 Emby 的计划任务。

### 能力

| 能力 | 说明 |
| --- | --- |
| 媒体库封面生成 | 读取媒体库素材（背景图 / 海报）+ 模板 + 字体 + 布局合成封面，可应用或直接上传成品图 |
| 13 套封面布局 | 扇形展开 / 斜线分割 / 旋转 / 旋转堆叠 / 极简 / 海报墙 / 经典堆叠 / 经典平铺 / 经典平铺(动态) / 聚焦C佬 / 荣耀视界（以上来自 ChillPoster）/ 暗场右文 / 分类横幅（自研） |
| 封面备份 / 恢复 | 批量导出为备份套件，可整体或按库恢复，带缩略图预览 |
| 自动封面任务 | 定时任务 + Emby 入库 webhook（复用宿主 `EventType.WebhookMessage`）触发对应库刷新 |
| Emby 任务中心 | 查看 / 编辑触发器（每天 / 每周 / 按间隔 / 服务器启动时）、立即运行、停止 |
| 通知 | 统一走 MoviePilot 通知渠道（`post_message`），不自建通道 |

布局参数表单**完全按布局的 `get_schema()` 自动生成**（分组 + 滑块 / 下拉 / 颜色 / 字体 /
开关 / 文本 / 文件），新增布局不需要改前端。

### 首次配置

1. 确认 MP 里已经配好 Emby 媒体服务器（插件不另存凭据，直接复用宿主的 `MediaServerHelper`）；
2. **上传中文字体**（封面设计 → 字体）——字体有版权，不随插件分发，未上传时中文会显示方块；
3. 选布局 → 调参数（右侧固定预览）→ 应用到媒体库；
4. 需要自动化就开「自动封面任务」，选库、选触发方式（定时 / 入库 webhook）。

### 排障

- **文字是方块** → 没上传中文字体，见上面第 2 步；
- **预览和成品不一样** → `canvas_preset=auto` 时只有「分类横幅」和 keyart 底图按原图尺寸，
  其余布局固定 1920×1080；
- **更新插件卡在「安装依赖」** → 本插件刻意不带 `pyproject.toml`，只用宿主自带的 Pillow；
  若卡住说明别的插件声明了依赖，和本插件无关；
- **Jellyfin 报 404** → Emby 用 `emby/…` 前缀，Jellyfin 用根路径，选错类型会打不通。

## 仓库结构

```text
MoviePilot-Plugins/
├── plugins.v3/
│   ├── subscribecenter/     # 胖虎订阅中心（Vue 联邦前端产物在 dist/assets/）
│   ├── tgmediacenter/       # 胖虎媒体中心
│   └── embycovercenter/     # 胖虎封面中心
├── tests/v3/                # pytest 测试（tg 593 / sub 708 / emby 128，共 1429）
├── icons/                   # 插件图标（索引仓库用；插件目录内另有一份随包发布）
├── docs/                    # 设计文档与配置清单
├── package.v3.json          # V3 插件索引（version / icon / history / labels）
├── CHANGELOG.md             # 阶段进度与版本里程碑
└── .github/
    ├── workflows/release.yml      # 发布工作流
    └── scripts/                   # 门禁脚本（版本校验 / 联邦 CSS 校验）
```

**发版流程**：push 到 `main` 且改动 `package.v3.json` → CI 跑两道门禁
（`check_plugin_versions.py` 版本四处同步、`check_federation_css.py` 联邦 CSS）→
只打包 `release: true` 的条目 → 打 tag `<PluginID>_v<version>` → 上传
`<插件id>_v<version>.zip` → Release 说明取自 `history["v<version>"]`。
同版本重跑会先删旧 Release 和 tag 再重建；插件目录自上次 tag 起没改动则跳过打包。
